# 08: 新增、拆分与合并字幕

Status: ready-for-agent
Blocked by: 03, 07
Spec: [WebUI 字幕与说话人编辑器](../spec.md)

**What to build:** 用户在播放头补字幕、拆分长句、合并连续短句；两段拆分结果先复制全文，跨人物合并由用户明确归属，整个过程可撤销并保留来源关系。

## 上下文与修改范围

- 对应用户故事 33、38–40、51–52；03 提供结构化来源及导出，07 提供可靠的连续多选和批量历史。
- 修改 WebUI 结构编辑操作、工具栏/快捷键、有效性校验与测试。字幕序号是导出表示，不是稳定身份。

## Acceptance criteria

- [ ] 新增从播放头开始，默认 2 秒，临近片尾缩短；采用当前明确轨道，否则归到 `?`，输入非空正文后才提交。
- [ ] 位于媒体终点时不能新增零时长条目；取消新增不保存空正文、不生成历史，新增不虚构源条目关联。
- [ ] 拆分按钮与 Ctrl+B 只对单条选中字幕生效，播放头严格位于内部；两条时间相邻、复制原全文和说话人，并继承来源及元标签。
- [ ] 合并按钮与 Ctrl+M 仅接受全体工作字幕时间排序中连续选中的条目；最早开始、最晚结束，正文按顺序换行，允许覆盖原空隙。
- [ ] 相同说话人可直接合并；跨说话人必须明确结果标签，取消选择不改变条目或历史。
- [ ] 合并保留参与条目的来源关系和元标签；条目身份、当前编号与来源索引保持区别，撤销能恢复原身份、内容、归属及来源。
- [ ] 每次新增、拆分或合并作为一个编辑操作；总览、人物轨、列表同步，保存重开及四种导出反映同一结果。
- [ ] 导出排序和重新编号不改写原来源索引，MOSS 导出段 ID 仍唯一；拆分复制全文不被额外算法擅自改成按时间猜字。

## Verification

1. 通过浏览器分别在片头、普通位置及片尾新增；在端点和内部尝试拆分，并核对两段的全文及时间。
2. 测试连续/不连续多选、同人/跨人、重叠/间隙合并，确认无效操作不改状态，撤销恢复全部原条目。
3. 导入带标签和来源的 JSONL 后执行结构编辑、保存重开并导出；用公共接口和实际产物检查来源、排序、身份及元标签，运行相关回归并记录结果。
