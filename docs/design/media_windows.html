连续模式

start = first_target.start - context_before - pre_roll
end = last_target.end + post_roll
  • context-before 秒的原片会完整保留，包括没有字幕的空白。
  • pre-roll 与 context 范围首尾相接，因此总前扩展是两者之和。
  • Compact 的三个参数全部忽略，不参与裁剪。

Compact 模式

selected = context_entries + target_entries
window = [entry.start - compact_pre, entry.end + compact_post]
windows = merge(window, compact_merge_gap)
  • context-before 只负责选择字幕，不保证完整保留对应秒数的视频。
  • 只有已选 context 和 target 附近的窗口被保留，其余空白删除。
  • pre-roll/post-roll 全部忽略，不会和 compact 扩展叠加。

为什么看起来像重复

context-before 和两类 roll 都会让模型看到 target 之外的媒体，但处在不同层级：

context-before = 先决定前文有哪些字幕值得带上
roll = 再决定这些字幕或整个 scene 周围保留多少画面

真实实现中的边界

连续模式把一个请求里的每个 scene 分别裁剪再拼接，多个 scene 的 context 可能在同一视频中重复。Compact 模式对整个请求统一去重和合并窗口，重叠原片不会重复播放。当前最佳基线使用单 scene/request，不涉及多 scene 连续重复。

对应实现：sub/llm/gemini_segment_diarize.py 的 _build_segments_from_json、_compact_windows_for_segments 和 _make_batch_clip。完整端到端流程见 pipeline_explorer.html。
