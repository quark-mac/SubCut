# 已有流程操作手册

用于用户要求运行、引导、检查或恢复现有工具时。项目进度见 [CURRENT.md](CURRENT.md)，命令参考见 [workflow.md](workflow.md)。

## 开始一次运行

1. 确认目标阶段、输入媒体/字幕和输出位置；已有信息直接从工程或文件读取。
2. 检查当前代码版本、输入版本及已有产物，选择可复用的结果。
3. 执行用户已授权的范围。涉及付费 API、覆盖或清理且授权范围不清楚时，补充确认费用范围或具体路径。
4. 检查本阶段产物，再继续依赖它的步骤；结束时报告结果位置和待处理问题。

新运行使用独立输出目录，记录输入、参数、模型和代码版本。仅重建报告或调整标签映射时，复用已有推理结果。

## 编辑器与 Diarize

- **人工校对**：按 [WebUI 使用说明](../webui/README.md#使用) 创建或打开工程，校对后保存，再导出字幕。
- **声学分段**：按 [voice/README.md](../voice/README.md) 运行推理或字幕关联；检查 `diagnostics.json` 中的候选、覆盖率及边界项。
- **标签映射**：匿名编号属于一次推理运行；按已确认的对应关系填写映射，再执行 export-only。
- **素材导出**：选择已校对的 SRT、媒体、角色、输出类型及合并规则；参数见 [extract_simple.md](skills/extract_simple.md)。

管理界面第一版的自动编排正在设计，范围与流程图见 [CURRENT.md](CURRENT.md#当前方向单视频管理界面)。

## DeepSeek / Gemini 操作检查

使用这一既有命令行流程时，按 [workflow.md](workflow.md) 的阶段执行：

| 阶段 | 完成条件 |
| --- | --- |
| Normalize | 报告和抽样字幕可读，条目非空、时间有效，来源关联完整 |
| Scene 计划 | 请求数量和输入范围符合目标 |
| Scene 生成/人工回写 | 目标条目完整覆盖、时间有序；保留语义场景边界 |
| Gemini 请求计划 | scene、目标 idx 和批次对应正确 |
| 媒体准备 | clips 可播放，声音/画面及 compact 时间映射对应原字幕 |
| Gemini 标注 | 目标与结果条目齐全，解析正常，标签符合提示词契约 |
| Gold 评估 | 使用当前 Gold 做时间/文本结构对齐，报告总体及重点角色指标 |
| 切片导出 | 报告、文件清单及产物数量对应，抽样媒体可播放 |

模型配置和密钥读取本地配置；运行记录仅保存可公开的参数。源字幕结构变化后，重建依赖它的场景和标注。

## 恢复与异常

| 已有状态 | 处理方式 |
| --- | --- |
| normalized 和报告齐全 | 核对输入版本后复用 |
| scene SRT 经人工编辑 | 使用 `scene_srt_to_json.py` 回写并检查覆盖 |
| scene 与输入字幕不对应 | 从选定字幕重新生成 scene |
| Gemini 局部目录已有结果 | 保留该次结果，另建运行目录 |
| 只有 results.jsonl，缺报告 | 使用 `--report-only` |
| 声学推理完成，仅需改角色映射 | 修改映射并重新导出字幕 |
| 导出目标文件已存在 | 选择复用、新目录或明确覆盖 |
| 解析、覆盖或媒体检查失败 | 保留日志，解决当前阶段后再继续 |

需要修实现时，记录命令、输入、预期/实际结果及错误日志，交给开发任务处理。

## Operator 入口

`.opencode/agents/kaguya-operator.md` 是运行已有工具的专用 agent，直接读取本手册；通用开发约定位于根目录 `AGENTS.md`。

配套 `kaguya-workflow` skill 保留为手动入口。它设置了 `opencode/autoinvoke: false`，因此从模型的可用列表隐藏；这与删除 skill 或把内容迁入 `AGENTS.md` 是两回事。参见 [OpenCode skills](https://opencode.ai/v2/docs/skills#frontmatter)。
